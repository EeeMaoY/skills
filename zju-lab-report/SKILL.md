# 浙江大学课程实验报告（Typst）

## 适用范围

用于**撰写、补写、编译、检查**课程实验报告。不涉及实验本身的实现与调试——那是各门课自己的 skill 负责。

各门课的差异（报告放哪、文件名前缀、章节骨架）**不写在本 skill 里**，而在：

- 项目级 skill：仓库 `.claude/skills/<课程>-lab-report/`
- 仓库 `CLAUDE.md`：长期不变的仓库约定

**动手前先读这两处**，本 skill 只讲跨课程通用的部分。

## 第一步：先侦察，不要凭印象

按顺序确认本仓库的既有约定，再动笔：

1. 仓库 `CLAUDE.md`；
2. `.claude/skills/` 下的课程专属 skill；
3. **仓库里已有的报告源文件**（`find . -name '*.typ' -not -path '*/ZJU-Project-Report-Template/*'`）——命名格式、前言写法、自定义函数照抄它的风格；
4. **课程给的报告模板**（Markdown，通常带 `<此处替换为...>` 占位符）——只提供**内容**（实验目的条目、必须给出的结果项、思考题题干），**不提供章节骨架**（骨架怎么定见下）。

不要自创与既有报告不同的风格，也不要把 Markdown 模板直接翻译成 Typst 交上去。

## 硬约束

| 约束 | 原因 |
| --- | --- |
| 模板以 **git submodule** 引用，**固定在 tag `v1.3`** | 不要往仓库里复制模板副本，改模板请提 PR 到上游 |
| **不要升级到 master** | master 用了 `image.decode()`，所有已发布的 Typst（含 0.15.1）都没有该函数，编译必然失败 |
| 用 `#import "<相对路径>/template.typ": *` 引入 | v1.3 的 API 是**蛇形命名**：`lab_header`、`codex`、`figurex`、`table3`、`blockx`；master 的烤串命名（`lab-header`）不适用 |
| 克隆后先 `git submodule update --init` | 否则 import 报文件不存在 |

## 编译与校验

```bash
typst compile --root <根目录> <报告源文件>
```

- **必须带 `--root`**：报告 import 的模板在源文件的上级目录，逃出了 Typst 默认的沙箱根（源文件所在目录），不加会报 `path ... would escape the project root`。`<根目录>` 取同时包含报告与模板 submodule 的目录，通常就是仓库根。
- 产物默认写在源文件同目录、同主文件名（`.pdf`）。只想校验又不想覆盖已有 PDF 时，显式给输出路径：`typst compile --root . x.typ /tmp/x.pdf`。
- **字体警告是噪声**（`unknown font family: georgia` 之类）。只要退出码为 0、PDF 生成，就算成功。
- 改完报告**务必真正编译一次**，不要只肉眼看源码就说完成。

## 章节骨架

**不要自己拍板骨架，按三步走：**

1. **优先在模板 submodule 的示例里挑**：`ZJU-Project-Report-Template/examples/` 下有 `co`／`dd`／`dip`／`fds` 四套 `.typ`，章名各不相同，从中选一套最贴近当次实验的。
2. **再参考别的模板**：同一作者此前的同类课程报告 `.typ`（排版与 TODO 写法的样板）、课程给的 Markdown 报告模板（只提供内容）。
3. **把候选骨架报给用户，确认后再动笔。**

同一门课不同 lab 的章名也可能不一样，不要跨 lab、跨课程套用。骨架定下来后，各小节要写什么由课程 Markdown 模板提供——它的章名不进入报告。

模板里凡是写着「（实验报告中请去除本段）」「（实验报告中请去除以上内容）」的说明段，**提交前必须删掉**；模板里的占位符（`<此处替换为实验名称>`、`<此处替换为学号>`）也要替换成真实内容。

## 排版惯例

| 用途 | 写法 |
| --- | --- |
| 代码 | `#codex(<代码>, lang: "c++")` |
| 终端命令与输出 | `#raw("$ make check_lab0\n...", lang: "bash")` 原样转录 |
| 提示框 | `#note[...]`、`#warning[...]`、`#tip[...]` 等（`blockx` 的别名，可加 `name:` 标题） |
| 表格 | `#table3(columns: (1fr, 2fr), [表头1], [表头2], [单元格...])` |
| 图 | `#figurex(image("images/labN/xxx.png"), "图注")` |

正文里 `*粗体*`、`_斜体_`、等宽用反引号；`~` 会渲染成不换行空格。

### 未完成处的占位

未完成的截图或内容用显眼的红色占位，在报告前言里自定义：

```typst
#let TODO(body) = text(fill: rgb("#C00000"), weight: "bold")[【待填：#body】]
```

实测输出放进提示框（`#success(name: [实际输出（xxx）])[ ... ]`）。截图未补时把图包在 TODO 里：

```typst
#TODO[粘贴……的截图；补图时把本行替换为 `#image("imgs/3.2.1.png", width: 80%)`]
```

- 示例里的 `#image(...)` **必须用反引号包住**，否则 Typst 会把它当代码求值；图片尚不存在时直接编译报错。
- 图片放报告同目录的 `imgs/` 下，**文件名与所在小节号一致**（3.2.1 小节的图叫 `imgs/3.2.1.png`），这样「位置」与「名字」不会对不上。
- 交付前 `grep '【待填】'` 一次性清理。

## 写作准则

1. **结果必须来自真实执行。**报告里的每条命令、每段输出、每个数字都要有实际来源；没实际跑过的不要写，跑不通或未跑的部分明确标注「未验证」或留 TODO，**绝不编造输出**。
2. **命令与输出按实际转录**，不要凭记忆重写、不要美化报错信息。
3. **书面语、有条理、图文结合**；分析要落到「为什么」，而不只是罗列「是什么」。
4. **截图**：垂直方向、先裁剪、不要过大；无图形界面时用终端文本转录替代，并在报告中说明这一替代。
5. **保留可见的 TODO**：未完成处用显眼占位（如红框 `【截图 TODO】`），便于作者自查；不要用看似完成的措辞掩盖缺口。

## 提交前检查清单

- [ ] 文件命名符合仓库既有格式（`<课程前缀>_<学号>_<姓名>_lab<N>`，前缀以已有报告为准）
- [ ] 章节骨架按三步流程选定、并经用户确认；模板说明段已删除、占位符已替换
- [ ] `typst compile --root <根目录> <源文件>` 退出码 0，PDF 与源文件同目录同名
- [ ] `git submodule status` 仍指向 v1.3（没有被升级到 master）
- [ ] 没有把模板副本误加进仓库
- [ ] 每条结果都有真实来源；未完成处有显眼 TODO
- [ ] 图已裁剪、方向正确、有图注
- [ ] **提交/推送前已征得用户同意**——报告改完不要顺手 `git push`
